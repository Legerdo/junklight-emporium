# 별고물 상회 — JUNKLIGHT EMPORIUM

## 자율형 원샷 게임 제작 프롬프트 · Claude Opus 5.5

완성된 **한국어 브라우저 기반 2D 픽셀 아트 액티브 인크리멘탈 게임**을 기획하고 실제로 제작하라. 제안서나 기능 시연이 아니라, 처음 실행한 사람이 플레이를 배우고 성장하며 엔딩까지 도달할 수 있는 게임이 결과물이다. 이 문서만으로 시작하며 다른 프롬프트나 원작 설치를 요구하지 않는다.

가장 중요한 경험은 **간단한 선택 한 번이 만족스러운 물리적 반응과 발견을 만들고, 수집한 아이템과 업그레이드가 그 결과를 계속 바꾸는 것**이다. 손맛만 좋은 짧은 데모도, 아이템 목록만 긴 숫자 게임도 이 목표를 충족하지 않는다.

## 1. 작품의 큰 틀

가제는 **「별고물 상회」**다. 플레이어는 버려진 물건을 수거하고, 기묘한 장치로 가공·복원하고, 그 안의 보물을 발견하는 작은 상회를 운영한다. 처음에는 낡은 물건 몇 개를 처리하지만, 성장하면 여러 장치와 물건의 성질이 맞물려 큰 연쇄를 일으킨다. 상회의 발전은 주변 세계의 복구나 변화로도 드러나야 한다.

핵심 흐름은 **관찰·선택 → 수거·작동 → 물건의 반응과 연쇄 → 보상·발견 → 재투자 → 달라진 다음 선택**이다. 수거 위치를 고르고 기계를 작동시키는 방식을 출발점으로 삼되, 더 직관적이고 재미있는 입력 방식이 있다면 바꿔도 된다. 마우스만으로 핵심 플레이가 가능하고 연타가 가장 효율적인 전략이 되지 않게 한다.

작은 행동을 장난감처럼 즐기는 감각, 기대감을 만드는 보상 공개, 서로 연결되는 성장, 직접 하던 일을 시스템이 수행하게 되는 변화를 참고한다. Fortune Mill, Bills Must Be Paid, Scritchy Scratchy는 이 방향을 이해하기 위한 레퍼런스이지 복제할 설계도가 아니다. 특정 원작의 기계·아이템·UI를 이름만 바꿔 가져오지 않는다.

초회 엔딩은 **60~90분 정도의 밀도 있는 경험을 초기 목표**로 삼는다. 시간은 실제 플레이에 따라 조정할 수 있으며, 목표 시간을 맞추려고 가격·반복 횟수·대기만 늘리지 않는다. 초반부터 재미가 있고, 중후반에도 새로운 발견과 조합이 남아 있어야 한다.

## 2. 네가 결정할 것

너는 구현자이면서 게임 디자이너다. **여기서 고정한 플레이 경험과 완성도는 지키되, 이를 달성하는 구체적인 설계는 직접 결정하라.**

제목의 개선, 세계관의 세부 설정, 화면 구성, 수거 방식, 물건과 장치의 종류, 아이템 효과와 희귀도, 장착 구조, 업그레이드 체계, 지역과 의뢰, 보상 확률, 가격, 해금 순서, 자동화 방식, 클라이맥스와 재플레이 구조는 네 재량이다. 정해진 아이템 수나 카탈로그를 채우는 과제가 아니다. 세트·스킬트리·프레스티지 같은 익숙한 시스템도 필요성이 있을 때 선택한다.

이 작품을 다른 인크리멘탈과 구별하는 **대표 상호작용**을 만들고, 여러 콘텐츠가 그 상호작용을 확장하게 하라. 익숙한 시스템을 전부 나열하는 것보다 하나의 발상이 여러 재미로 이어지는 편을 택한다. 의외의 조합을 발견할 여지를 남기되, 설명서를 외워야 작동하는 조합 퍼즐로 만들지 않는다.

더 나은 방법을 발견하면 초기에 정한 설계도 수정할 수 있다. 바꾼 이유는 짧게 기록하면 충분하다. 사소한 결정을 사용자에게 넘기거나 후보 목록만 제시하며 멈추지 않는다. 반대로 구현이 쉽다는 이유로 수집·성장·조합·중후반 콘텐츠를 지워 얇은 데모로 축소하지 않는다.

## 3. 콘텐츠와 성장의 품질 기준

**아이템에는 얻고 싶은 이유와 사용할 이유가 있어야 한다.** 새 도구나 수집품을 얻으면 대상으로 삼는 물건, 가공 결과, 연쇄 방식, 선택의 우선순위 중 무언가가 달라져야 한다. 외형·희귀도·수입 배수만 바꾼 복제를 주된 다양성으로 삼지 않는다. 모든 아이템에 복잡한 규칙을 붙일 필요는 없지만 핵심 아이템에는 구별되는 역할과 조합 가치가 있어야 한다.

**성장은 수직·수평으로 함께 일어나야 한다.** 더 많이 처리하고 더 크게 반응하는 성장에 더해, 다른 도구·조합·운영법을 택할 이유를 만든다. 서로 다른 빌드가 상황에 따라 장단점을 가지며, 선택을 바꾸면 실제 플레이도 달라져야 한다. 시작 장비와 이전 콘텐츠도 새로운 요소와 만나 다시 쓸모가 생기게 한다. 잘못 고른 장비 때문에 장시간 진행을 잃지 않도록 실험과 교체를 허용한다.

**콘텐츠는 성장 전 과정에 배치한다.** 초반에는 작은 규칙을 익히고, 중반에는 기존 요소의 연결을 발견하고, 후반에는 자신이 구축한 시스템을 활용하는 새로운 목표에 도전하게 한다. 새 지역이나 단계는 색과 가격만 다른 배경이 아니라 다른 선택·상호작용·상황을 제공해야 한다. 의뢰와 수집 목표도 같은 판매량 과제의 반복보다 다른 플레이를 유도하는 데 사용한다.

**보상은 예측 가능한 진척과 예상 밖의 발견을 함께 준다.** 평범한 결과도 다음 목표에 기여하고, 드문 결과는 눈에 띄는 사건이 된다. 필수 진행을 희귀 드롭이나 대박에만 맡기지 않는다. 화폐와 관리 항목은 목적이 분명한 만큼만 두고, 장시간 무의미한 대기 없이 다음 구매·발견·실험으로 이어지게 한다.

**자동화는 역할의 변화다.** 반복 작업은 시스템에 맡기되, 플레이어에게 다음 목표와 조합을 결정할 이유가 남아야 한다. 자동화 때문에 모든 선택이 사라지거나 일부러 불편하게 만들어 수동 연타로 돌아가게 하지 않는다.

**종착점과 그 이후가 있어야 한다.** 세계의 변화와 연결된 명확한 목적, 지금까지 배운 상호작용을 활용하는 클라이맥스, 엔딩을 만든다. 엔딩 뒤에는 다른 빌드·수집·조건 변화 등을 통해 다시 플레이할 이유를 남긴다. 재시작을 사용한다면 보존되는 성취와 새롭게 달라지는 경험을 분명히 하고, 필수 반복 노동으로 쓰지 않는다.

구체적인 콘텐츠 양은 직접 정하되, **초중후반의 변화와 서로 다른 유효 빌드를 실제 플레이로 보여줄 수 있을 만큼** 확보하라. 목록의 길이나 선언한 기능 수가 아니라, 플레이어가 계속 새로운 선택과 결과를 경험하는지로 충분함을 판단한다.

## 4. 손맛과 표현

첫 기본 행동부터 **입력 → 짧은 기대 → 접촉·변형 → 주변 반응 → 보상**이 연결되어야 한다. 물건의 무게와 재질, 도구의 움직임, 애니메이션과 효과음이 서로 맞물리게 한다. 작은 충돌, 큰 연쇄, 희귀 발견, 최종 사건은 강약을 구분한다. 크게 터지는 장면도 원인과 결과를 읽을 수 있어야 하며, 긴 연출이나 상시 흔들림으로 반복 플레이를 피곤하게 만들지 않는다.

성장은 숫자뿐 아니라 화면과 소리에 나타나야 한다. 후반에는 기계의 동작, 처리되는 물건, 연쇄의 규모와 방식, 상회와 주변 환경이 초반과 달라 보여야 한다. 음악과 효과음은 장식이 아니라 작동·기대·보상의 피드백으로 사용한다.

아트 방향은 **낡았지만 생동감 있는 기묘한 상회, 읽기 쉬운 픽셀 실루엣과 재질, 물건이 실제로 움직이는 장난감 같은 공간**이다. 구도·팔레트·캐릭터·기계 디자인은 직접 정한다. 색만 다른 사각형, 이모지 아이콘, 화면 전체 픽셀화 필터를 완성 에셋으로 대신하지 않는다. 애니메이션 중에도 픽셀의 기준과 앵커가 안정적이어야 한다.

첫 화면의 주인공은 게임 공간이다. 동일한 카드 상자로 사방을 채운 관리 대시보드, 플레이 영역을 가리는 큰 설명 패널, 모든 성장 항목의 상시 노출을 피한다. 현재 할 일과 다음 목표는 명확하게, 상세 정보는 필요할 때 열리게 한다. 핵심 조작은 실제 행동으로 가르치고, 텍스트는 한국어로 짧고 읽기 쉽게 작성한다.

음량·화면 흔들림·섬광·동작 감소와 반복 연출 속도를 조절할 수 있게 한다. 효과를 줄이거나 음소거해도 게임 정보와 정산 결과는 유지되어야 한다.

## 5. 제작과 작업 자율성

기본 구현은 **TypeScript + Phaser 3 + Vite**, 텍스트 중심 메뉴에는 HTML/CSS, 오디오에는 Web Audio를 권장한다. 동일한 2D 웹 게임을 더 적절하게 완성할 수 있다면 엔진·물리·렌더링 구성은 이유를 기록하고 조정해도 된다. Windows 11에서 실행 가능하게 하고 설치·실행·빌드 명령을 제공한다.

게임 규칙과 저장 가능한 상태를 화면 연출에서 분리하고, 콘텐츠·밸런스는 수정하기 쉬운 데이터로 관리한다. 구조는 현재 게임에 필요한 만큼만 만든다. 별도의 범용 게임메이커나 과도한 프레임워크 개발로 범위를 넓히지 않는다.

오리지널 에셋은 코드 드로잉·절차적 애니메이션·사용 권한이 확인된 로컬 리소스 등 사용 가능한 수단으로 제작한다. GPT 기본 이미지 생성·편집 도구는 호출하지 않는다. 별도 유료 서비스나 API 키가 없다는 이유로 제작을 멈추지 않는다.

기존 작업 폴더가 있으면 먼저 해당 지침과 현재 상태를 읽고 기존 변경을 보존한다. 없으면 독립 프로젝트를 만든다. 승인되지 않은 외부 공개·비용 발생·사용자 데이터 삭제는 하지 않으며, 그런 작업이 필요해도 그와 무관하게 가능한 로컬 제작은 계속한다.

작업 접근법과 구현 순서는 스스로 정한다. 다만 기본 행동을 확인한 뒤에는 **구매·아이템 효과·성장·엔딩까지 이어지는 전체 흐름을 일찍 연결하라.** 첫 장면의 파티클만 계속 다듬다가 중후반을 남겨 놓지 않는다. 실제 결과를 보며 콘텐츠와 연출을 함께 개선한다.

긴 작업에서는 설계 결정, 구현·검증 상태, 다음 작업을 작은 진행 기록에 남겨 이어서 작업할 수 있게 한다. 서브에이전트는 사용 가능하고 독립된 큰 작업에 도움이 될 때만 활용한다. 분업 자체나 반복 재검토가 목적이 되어서는 안 된다.

**진행 보고나 다음 단계 예고만으로 작업을 종료하지 않는다.** 미완료 항목이 있고 실행 가능한 다음 작업이 있으면 이어서 수행한다. 사용자 판단 없이는 어떤 작업도 진행할 수 없는 실제 차단 요인이나 도구·세션의 한계가 있을 때만 중단 사유와 남은 상태를 정확히 남긴다. 사용할 수 없는 도구나 무제한 실행을 가정하지 않는다.

## 6. 완료를 판단할 근거

검증 방법은 환경에 맞게 선택하되, 다음 사항은 실제 결과로 확인할 수 있어야 한다.

- **시작과 완주:** 신규 저장에서 기본 조작, 보상, 첫 구매가 연결되고 이후 성장과 엔딩까지 진행 경로가 실제로 존재한다. 초중후반에 무엇을 해야 하는지 화면에서 알 수 있다.

- **선택과 콘텐츠:** 주요 아이템은 정상적인 획득 경로를 가지며 장착·구매 후 실제 효과가 발생한다. 서로 다른 빌드의 선택과 결과를 비교할 수 있고, 새 단계가 이전과 다른 상황을 제공한다. 설명만 있는 효과나 도감에만 존재하는 콘텐츠는 미구현이다.

- **경제와 연쇄:** 정상 진행에서 의미 없는 대기가 반복되지 않는다. 복제·연쇄·자동화가 있다면 무한 처리, 중복 보상, 필수 물건 소실을 막는다. 장식 효과의 양이나 속도가 경제 결과를 바꾸지 않는다.

- **실제 화면과 입력:** 브라우저에서 직접 핵심 행동을 실행하고 대표적인 초중후반 화면과 큰 연쇄를 확인한다. 모달 입력 충돌, 가독성, 픽셀·애니메이션 품질, 후반 성능을 확인한다. 콘솔 오류 없음과 스크린샷 한 장만으로 이 항목 전체를 통과시키지 않는다.

- **저장과 빌드:** 자동 저장·새로고침·재진입으로 성장이 복구되고, 처리 도중 중단되어도 보상이 중복되거나 진행이 사라지지 않는다. 실제 production build가 실행된다.

정상 경제 플레이, 가속 시뮬레이션, 개발용 강제 해금은 구분해 기록한다. 후반을 강제로 열어 기능을 확인한 것을 정상 완주나 밸런스 검증이라고 보고하지 않는다. 이해도와 재미에 대한 자체 평가는 실제 사용자 테스트와 구분한다.

실패가 발견되면 고치고 관련 검사를 다시 수행한다. 기준을 충족했고 새로운 문제나 변경이 없다면 같은 검증을 반복하지 말고 결과물을 전달한다. 환경 제약으로 확인하지 못한 것은 미검증으로 남기며, 완료 기준을 낮춰 통과한 것으로 바꾸지 않는다.

## 7. 결과물

실행 가능한 전체 소스와 에셋, 의존성 잠금 파일, 실행·빌드 방법, production build, 수행한 테스트와 핵심 검증 기록을 제공하라. 최종 응답은 **실행 방법과 결과물 → 실제 구현된 성장·콘텐츠 → 수행한 검증 → 남은 제한** 순서로 간결하게 작성한다.

**같은 간단한 행동이 내가 발견하고 선택한 도구·아이템·업그레이드 때문에 점점 다른 놀이가 되어야 한다. 그 경험을 가장 잘 만드는 세부 설계를 직접 선택하고, 작동하는 게임으로 완성하라.**
